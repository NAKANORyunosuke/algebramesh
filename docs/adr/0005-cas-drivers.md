# ADR 0005: Macaulay2 と OSCAR の driver

- 状態: 採用
- 日付: 2026-11-03
- 関連: 設計書 §5.4, §6, §8, §9, §11, §15「Macaulay2/OSCAR の機械可読出力」

## 背景

Macaulay2 と OSCAR は OpenXM を前提としない.
設計書は, 専用 driver を subprocess として動かすこと, 入力を検証済みの template から組み立てること, 人間向けの標準出力を標準のデータ形式としないことを求めている.

## 確認した事実

- Macaulay2 1.24.11 (Debian trixie): `HolonomicSystems` 1.0 の `gkz` は外部プログラム 4ti2 を必要とする.
- `gkz(A, beta)` の環の変数順は `x_1..x_n, D_1..D_n` で, `listForm` は正規順序 (x が左, D が右) の指数を返す.
- `toricIdealPartials(A, W)` が返すイデアルは W ではなく D 変数だけの環にあるので, W へ写してから比べる必要がある.
- `toJSON` は有理数 1/2 を `.5` (浮動小数点) で出す. 係数には使えない.
- `using Oscar` に約 18 秒かかる (OSCAR 1.8.2, Julia 1.11.9, precompile 済み).
- OSCAR の `factor` は, QQ 上では `unit` に定数部を, ZZ 上では定数を因子として返す. 有理数は `1//2` と表記される.

## 決定

### 共通の約束

- driver の答えは標準出力の1行 `ALGEBRAMESH_RESULT {json}` または `ALGEBRAMESH_ERROR message` とする. それ以外の出力はログとして保存し, データとして解釈しない.
- CAS には変数名もソースコードも渡さない. 多項式は添字付き変数 (`t_i`) 上の指数ベクトルで受け渡す. 係数は `^-?[0-9]+(/[0-9]+)?$` に一致する文字列だけを数値に変換する.
- CAS の結果は Rust 側で型付きの値に戻し, CAS に依存しない検算を行う.
  - 因数分解: 因数の積が入力と一致すること.
  - GKZ: Euler 作用素が `sum_j a_ij x_j d_j - beta_i` と単元倍を除いて一致すること, toric 生成元がすべて `Au = Av` を満たす二項式 `d^u - d^v` であること.
- Gröbner 基底を要する判定は CAS に任せ, 結果に判定名を付けて記録する.
  - イデアルが toric + Euler で生成されるか.
  - 指定した作用素がイデアルに属するか.
- 締切超過と取消しではプロセスグループごと終了させる (Unix).

### Macaulay2

- ジョブごとに `M2 --script drivers/macaulay2/algebramesh.m2 request.json` を起動する. 起動は 1〜2 秒で済むので常駐させない.

### OSCAR

- 読み込みが遅いので, slot ごとに Julia プロセスを常駐させ, 標準入力で1行1要求の JSON を送る.
- 正常に答えたプロセスだけを再利用する. 締切超過・取消し・異常終了のプロセスは捨て, 次のジョブで起動し直す.
- 出力の上限 (Issue #12): 1 回の要求 (と起動) で標準出力から読むバイト数を `max_output_bytes` (既定 256 MiB, Macaulay2 の driver と同じ) までとする. 行は上限の分までしか持たないので, 改行のない巨大な出力でも worker のメモリは増え続けない. 上限を超えたら `RESOURCE_LIMIT` とし, 出力の途中で止めたプロセスは捨てる. ジョブのログに残す出力の行は 64 KiB までとし, 残りは行数だけ記録する. 標準エラーは 8 KiB ずつ読み, agent のログに流すだけで蓄えない.
- プロセスグループの回収 (Issue #90): Julia は Unix で自身のプロセスグループを作る. 起動の直後からグループを止める guard を持ち, 準備ができたプロセスに引き渡す. 起動の失敗 (起動の期限切れ, 不正な ready 行, 出力の上限超過), 起動を待つ間の取消しと締切超過, プロセスを捨てるとき, backend とともに待機中のプロセスを捨てるときのどれでも, Julia が作った子孫ごと止め, 標準エラーを読む task も止める.
- Singular は OSCAR 経由でだけ使い, 直接の統合は作らない (設計書 §8).

## 検証

Docker 上の cluster で次を確認した.

- `x^4-y^4` の因数分解の型付き結果が, Asir・Macaulay2・OSCAR の3つで一致した.
- 設計書 §9.2 の GKZ 系について, 上記の検算と CAS による判定がすべて成り立ち, 期待生成元3つがすべてイデアルに属した.
- 版情報 (`Macaulay2 1.24.11`, `OSCAR 1.8.2`, Asir `20260331`) が agent 登録時に scheduler に記録された.

## 残る課題

- Macaulay2 の要求ファイルは一時ディレクトリに書く. 大きな入力では標準入力で渡す形に改めてよい.
- GKZ の indicial ideal, 級数解, 数値計算 (設計書 §9.3 の 2〜4 段階) は未実装.
